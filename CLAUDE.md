# Blast Radius — read this first

Blast Radius runs an npm MCP server inside a Wasmer sandbox against a fake home
folder of planted secrets, records every file and network request the sandbox
saw, and prints a verdict card. Built at the AI Security Hackathon, SF,
2026-09-13, Wasmer track. Two people: Adan and Seiji (git author "HeapSmasher"),
each with their own Claude session.

Read in this order: this file, `README.md`, `docs/FINDINGS.md`. The findings
doc is the memory of the project: every trap in it cost real time, and the
parser, runner and analyser encode them. Do not touch `src/parse.mjs`,
`src/detonate.mjs` or `src/analyse.mjs` without reading it.

## Fresh machine

```sh
node --version                                  # 23+
curl -sSfL https://get.wasmer.io | sh           # 7.4+, lands in ~/.wasmer; detonate.mjs calls it by path
cd specimens && npm install --ignore-scripts    # the lockfile pins all 16; NEVER let install scripts run
node run.mjs @modelcontextprotocol/server-memory   # first run downloads edgejs (~1.5 min), then <1 s boots
```

No API keys anywhere. Every key in `src/specimens.mjs` is fake on purpose:
egress is denied, and a server that ships a fake key somewhere is the
behaviour we are here to observe.

## Commands

```sh
node run.mjs <pkg> [--env K=V]... [--arg X]...      # block-all (default): one card in .run/
node run.mjs <pkg> --net vendor [--allow HOST]...   # vendor-only benchmark; needs a block-all card first
node run.mjs evil-notes --allow-sink                # with `node harness/sink.mjs &` running from the repo root
node run.mjs <pkg> --engine quickjs                 # engine inside the sandbox too (~3x slower boots)
node harness/boot-test.mjs [filter]                 # SPECIMENS.md + evidence/boot-test.json
node harness/sweep.mjs [filter] [--net vendor] [--index-only]
node harness/report.mjs [--fragment out.html]       # evidence/cards/index.html
```

Full regeneration after a pipeline change, in this order: boot-test, sweep,
sweep `--net vendor`, the control with the sink (`--allow-sink`, then copy
`.run/evil-notes.{json,html}` to `evidence/cards/`), report, commit
`evidence/cards/`.

## Rules that the code does not explain

- **Two claim tiers, never mixed.** Everything from the syscall trace is
  observed. Only a canary string found in what the collector received is
  proven. `canary_in_payload` is never derived from the trace; payload bytes
  are not in it.
- **Three verdicts, all descriptive.** *expected* (only did what its job or our
  request implied), *undeclared* (reached a host outside its vendor, or opened
  or changed something nobody asked for), *critical* (planted secret provably
  left, or opened unprompted right before a connection attempt). The policy
  that decided "expected" is recorded in `findings.policy`. "Did not run" is
  not a verdict. Environment reads are shown, never scored.
- **No verdict for a server that never answered `initialize`.** A CLEAN card
  for a server that died on load would be a false claim; `run.mjs` exits 2.
- **Describe, never accuse.** Cards name real packages. "Undeclared" is a fact
  for the reader, not a finding of malice. Every card footer says one run is
  not a reputation.
- **Plain language everywhere users read.** The report and card copy is
  written for engineers who are not security people: "reached out to",
  "planted secret", "our collector", never egress, canary, sink, exfiltration.
  Keep it that way when adding text.
- **Block-all is the default and the safe benchmark.** Vendor-only sends real
  traffic to the vendor with fake keys; it exists to show whether a server
  reaches anywhere new once it can do its job.
- **The trace is the instrument, the CLI is the surface.** `@wasmer/sdk`
  exposes neither the syscall trace nor per-host `--net` rules, so the runner
  shells out to `wasmer run`. See FINDINGS before changing that.
- **Two Edge.js packages.** `wasmer/edgejs` (V8 on the host through N-API,
  fast, and per Wasmer's own security note not yet a hardened engine sandbox)
  and `wasmer/edgejs-quickjs` (engine inside the sandbox). Findings were
  identical across the whole sweep; `--engine quickjs` is the hardened path.
- **Tests are the saved evidence.** `analyse.mjs` is pure: after any change,
  re-run it over `evidence/cards/*.json` events and diff the verdicts before
  re-running anything under Wasmer. `docs/FINDINGS.md` "Two engines" shows the
  pattern.

## Known gaps, in priority order

1. `fixtures/world/app/.env` (the AWS canary) is never mounted: `detonate.mjs`
   mounts `specimens/` at `/app` and only the world's `home/` at `/home`. Only
   the SSH key and the `GITHUB_TOKEN` env canary are live today. Mount the
   world's `.env` somewhere a server would look (`/home/.env`) or drop it.
2. In-place file writes (open then `fd_write`) are not attributed to a path;
   only rename and unlink count as writes. `parse.mjs` already does fd
   bookkeeping for sockets; extend it to files.
3. Environment variable reads are invisible (`environ_get` reports sizes only);
   a leaked token is caught only at the collector.
4. Vendor detection is a name heuristic (`vendorTokensFor` in `analyse.mjs`).
   A package whose API domain does not match its name reads as undeclared
   until `vendor: [...]` is added to its manifest entry.
5. One execution path: every tool is called once with made-up arguments
   (`argsFor` in `detonate.mjs`). Behaviour that needs real data, a second
   call, or a date will trace clean.
6. `@sentry/mcp-server` hangs at startup; `@playwright/mcp` refuses the wasi
   platform; `@stripe/mcp` is a proxy with no local tools; Python MCP servers
   cannot run at all (`rpds-py` has no wasm build). All recorded, none fixable
   here.
